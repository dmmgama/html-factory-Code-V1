O que é esta aplicação

Em linguagem simples

É uma folha de cálculo inteligente dos teus projetos de IA. Abre no browser, não precisa de internet, não tem servidor. Tudo fica guardado no próprio browser (localStorage).

Tens 44 projetos catalogados. Para cada um podes dizer se te interessa, a que domínio pertence, qual o estado, e como se relaciona com os outros. Podes exportar para Excel, CSV, JSON ou Markdown.

Para um agente AI ler

SPA offline de ficheiro único (HTML + CSS + JS). Estado em localStorage["curador-projetos-ai-v3"]. Nenhum fetch, nenhuma API.

Para mudar um dado: muta STATE.projetos[i].campo e chama commit(). Para ler o que está visível: filtered() → sortRows(). O DOM reconstrói-se sempre do zero — nunca guardes referências a elementos.

Os 3 blocos internos

A app está dividida em 3 responsabilidades que nunca se misturam. Se precisas de mudar alguma coisa, sabes logo onde ir.

📦 DADOS

O que existe de facto. Dura entre sessões.

Onde vive:
  • 🔵 STATE.projetos[] — os 44 projetos
  • 🔵 STATE.links[] — as relações
  • 🔵 STATE.domains[] — lista de domínios
  • 🔵 STATE.domainTree — hierarquia de domínios
  • 🔵 UI — prefs de interface
Persistência: localStorage
Funções: load() save() normalize()

⚙️ MOTOR

Calcula, filtra, ordena. Nunca toca no DOM.

  • 🟠 passesFilter(p) → boolean
  • 🟠 filtered() → projetos visíveis
  • 🟠 sortRows(rows) → ordenados
  • 🟠 projDomPai1(p) → ancestral de topo
  • 🟠 projDomPaiImediato(p)
  • 🟠 domWouldCycle() → anti-ciclo
  • 🟠 computeGroups() → clusters
Regra: lê STATE, devolve valor. Nunca escreve no DOM.

🖥️ VIEWER

Desenha. Parte do zero em cada chamada.

  • 🟢 renderAll() — coordena tudo
  • 🟢 renderBody() — linhas da tabela
  • 🟢 renderHead() — cabeçalho + sort
  • 🟢 renderFilterBar() — filtros
  • 🟢 renderGraph() — SVG de ligações
  • 🟢 renderCronologia()
  • 🟢 renderAtribuicoes()
Regra: lê STATE + UI, escreve no DOM. Nunca guarda nada.
o ciclo de vida de uma edição
utilizador clica / arrasta / escreve ↓ handler de evento (inline no renderBody ou event listener) ↓ muta STATE diretamente → ex: p.interesse = "sim" ↓ commit() = save() + renderAll() ↓ localStorage atualizado + DOM reconstruído do zero

As 4 vistas (tabs)

📋 Tabela

A vista principal. 19 colunas, todas reordenáveis e redimensionáveis por drag. As colunas assinaladas como fact são só-leitura (vêm dos dados de fábrica). As restantes são editáveis diretamente na célula.

nome interesse ✎ domínios ✎ domínio pai 1 ✎ pai imediato ✎ prioridade ✎ estado ✎ cronologia ✎ nasceu de ✎ relevância origem stack plataformas git caminho ligações ✎ tags ✎ notas ✎ notas-fonte

cinzento = só leitura  |  azul ✎ = editável

🕸️ Ligações (Grafo)

Grafo SVG das relações entre projetos. Dois modos:

  • Força — posicionamento livre por simulação física; podes arrastar os nós
  • Mind map — árvore hierárquica baseada em "nasceu de"

Clica num nó → seleciona como origem. Clica noutro nó → cria ligação. Clica numa aresta → apaga ligação. Painel lateral para esconder projetos ou filtrar por tipo de relação.

Cor dos nós: ativo · pausado · ideia · arquivado / não interessa

📅 Cronologia & Genealogia

Duas sub-vistas numa só tab:

  • Cronologia — lista ordenada por data dos projetos que têm o campo cronologia preenchido (formato AAAA-MM). Apenas 7 dos 44 têm data no seed.
  • Genealogia — árvore de "nasceu de". Mostra quais projetos evoluíram de outros. Podes editar o pai diretamente na árvore com proteção anti-ciclo.

🗃️ Atribuições

Drag-and-drop para atribuir campos categóricos em massa. Campos disponíveis: Domínio, Estado, Prioridade, Interesse, Relevância, Tags.

Modo subdomínios (V3) — navega a hierarquia de domínios nível a nível com breadcrumb. Cada caixa é um domínio; arrasta projetos entre caixas. Podes criar, renomear e apagar subdomínios inline.

Domínios e a sua hierarquia novidade V3

Os 6 domínios de fábrica

  • 🔵 Aplicado JSJ — projetos de engenharia real (CAD, LSP, obra)
  • 🧠 Meta — projetos sobre projetos, governança, organização
  • 🔧 Tools — ferramentas e utilitários AI
  • 📚 Conhecimento — wikis, vaults, contexto, KB
  • 🌱 Vida — projetos pessoais não-profissionais
  • 🏗️ Infra — MCPs, pipelines, infraestrutura

Como a hierarquia funciona

Cada domínio pode ter um domínio-pai, formando uma árvore. Por exemplo: AutoLISP pode ser subdomínio de Aplicado JSJ.

A app calcula automaticamente para cada projeto:

  • Domínio pai nível 1 — o ancestral de topo na árvore
  • Domínio pai imediato — o pai direto do domínio mais específico

Podes fazer override manual por projeto se o cálculo automático não der o resultado que queres.

Versões e guardar

Auto-save

Cada vez que editas algo, a app guarda automaticamente em localStorage. Não precisas de carregar em nenhum botão. Se fechar o browser, não perdes nada.

Snapshots nomeados

Podes criar snapshots do estado atual com um nome (v1, v2, pré-reorganização, etc.) e voltar a eles mais tarde. Ficam guardados num localStorage separado.

Import / Export

Exporta tudo de uma vez: JSON (estado completo), XLSX (3 folhas: projetos, ligações, domínios), CSV e Markdown. Importa qualquer um destes formatos.

Repor fontes (Reseed) — Atualiza os campos de fábrica (caminho, stack, git, etc.) a partir dos dados originais, sem tocar na tua curadoria (interesse, domínios, notas, ligações). Útil se os dados de fábrica forem atualizados.

O que mudou na V3 (em relação à V2)

Filtros partilhados

Na V2, cada vista tinha os seus filtros independentes. Na V3, os filtros são globais e aplicam-se em todas as vistas ao mesmo tempo. Filtras na Tabela → o Grafo e as Atribuições também filtram.

Hierarquia de domínios

Na V2, os domínios eram uma lista plana. Na V3, tens uma árvore: cada domínio pode ter um pai, criando níveis. A app calcula automaticamente "domínio pai nível 1" e "pai imediato" para cada projeto.

Drill-down nas Atribuições

Nas Atribuições (V3), podes navegar a hierarquia de domínios nível a nível — como uma pasta de ficheiros. Ver os subdomínios de "Aplicado JSJ", depois os sub-sub, etc. Com breadcrumb de navegação.

Migração automática V2 → V3

Se tiveres dados guardados na V2, a V3 importa-os automaticamente na primeira vez que abres. Os teus dados de curadoria (interesse, domínios, notas, ligações) são preservados. Os dados de fábrica são atualizados.
