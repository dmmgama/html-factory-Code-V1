Mental Map: Arquitetura do teu Curador

O teu projeto traduzido nas 3 Caixas Universais para saberes sempre como falar com o Claude.

Módulo de Dados: Aqui vive a "Verdade Canónica" (SSOT). Não há estilos, não há HTML, não há cores. Apenas factos crus em formato JSON.

O Estado em Memória (STATE)

Quando a app arranca, ela guarda tudo numa caixa central chamada STATE. Ela contém:

  • STATE.projetos: Lista com todos os teus projetos brutos.
  • STATE.links: O mapa topológico que diz quem está ligado a quem.
  • STATE.dominios: A árvore de categorias/pastas.

Regra de Ouro para o Agente

"Se eu quiser guardar uma informação nova (ex: orçamento, tags), tu deves alterar a estrutura do JSON na Caixa de Dados, e nunca criar variáveis soltas no HTML."

Módulo do Motor: Funções matemáticas e lógicas. Elas leem a Caixa de Dados, processam as regras, mas NÃO sabem o que é um ecrã ou uma cor.

As Engrenagens Ativas (Funções de Lógica Pura)

Estas funções servem apenas para calcular caminhos e relações:

  • projById(id): Vai ao armazém de dados e encontra o projeto correto pelo número de ID.
  • calcGeral(): Conta quantos projetos existem em cada estado (ideia, execução, concluído) para gerar estatísticas puras.
  • obterFilhos(parentId): Varre as ligações topológicas para descobrir que projetos dependem deste nó pai.

Regra de Ouro para o Agente

"Quando eu quiser mudar a regra de dependência ou criar um filtro novo, altera apenas o motor de processamento. Estas funções devem receber dados e devolver dados calculados, sem mexer no DOM."

Módulo do Viewer: O Designer. Ele recebe os cálculos prontos do Motor e transforma-os em caixas visuais, tabelas ou grafos na interface.

As Lentes Visuais (Funções de Renderização)

Estas funções criam o código HTML que tu vês e clicas:

  • renderAll(): O maestro visual. Limpa a tela e chama a lente ativa.
  • renderTable(): Pega nos dados do motor e desenha as linhas e colunas rígidas.
  • drawGraph(): Usa o motor de grafos para desenhar caixas e calcular onde colocar as setas (edges) no ecrã.
  • renderSubdomView(): Desenha a árvore de pastas e subpastas tátil.

Regra de Ouro para o Agente

"O Viewer é burro. Se eu quiser mudar o aspeto de um card ou a largura da barra lateral, mudamos apenas o HTML/CSS gerado por estas funções. O Viewer apenas projeta o que o Motor calculou."

O Circuito Fechado: O que acontece quando tu clicas em "Mudar Estado" de um projeto?
1
Ação do Utilizador (Interface): Tu clicas num botão visual (Viewer) para mover um projeto de "Ideia" para "Execução".
2
O Motor é Avisado: O clique dispara uma função de alteração (ex: updateProjectState(id, 'execucao')). O motor valida se a ação é permitida.
3
Mutação nos Dados: O Motor altera o valor dentro do STATE.projetos. A fonte da verdade mudou em memória!
4
Atualização Visual: O Motor chama o renderAll() do Viewer. O Viewer lê os novos dados atualizados e redesenha a interface correta para o teu cérebro.
