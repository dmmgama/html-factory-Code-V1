Tour Guiado — 8 Passos

A arquitectura da app explicada na linguagem do Arquitecto: blocos de construção, contratos e plantas. Use a sidebar ou os botões Anterior / Próximo.

Diagrama da Caixa Tripartida

A app como um edifício de três pisos. Clica em cada piso ou seta para ver os detalhes do módulo.

SSOT / DADOS

A Planta Estrutural

Vive em localStorage. O objecto STATE em memória é a cópia viva. Nunca é alterado directamente pelo Viewer.

MOTOR

O Sistema Nervoso

Funções puras. Lêem o SSOT, devolvem dados calculados. Não sabem o que é um botão, uma cor ou um pixel.

VIEWER

A Fachada

Funções render*(). Recebem dados calculados e pintam o DOM. Não guardam estado. São descartáveis.

Mapa do Contrato de Dados

Os 20 campos do objecto Projecto — a junta de dilatação entre SSOT e Motor. Clica num campo para ver os detalhes.

Campos Factuais — vêm do SEED (dados originais). Representam a realidade da obra: o que o projecto é, onde vive, que tecnologias usa. O Arquitecto não os altera — são as medidas tomadas no terreno.
Campos de Curadoria — são as decisões do Arquitecto: a que domínio pertence, que prioridade tem, que notas acrescenta. Estes são os campos que o Arquitecto edita inline na Tabela.

As 4 Vistas — Outputs do Viewer

Quatro perspectivas sobre o mesmo SSOT. Cada vista é uma "fachada" diferente, construída pelo Viewer a partir dos mesmos dados calculados pelo Motor. Clica num card para expandir.

Nota de arquitectura: todas as 4 vistas partilham a mesma barra de filtros (novidade V3 — antes cada vista tinha os seus próprios filtros independentes). O Motor recalcula filtered() uma única vez e todas as vistas consomem o mesmo resultado.
