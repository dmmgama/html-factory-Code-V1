Diagnóstico — Ecossistema AI

David Gama · Sessão de trabalho · Abril 2026

Este documento captura o diagnóstico completo do estado actual do ecossistema pessoal de ferramentas AI, realizado durante uma sessão de trabalho sobre o CWPP (Claude Web Projects Protocol). O diagnóstico revelou que o problema não é técnico — é arquitectural.

1. Contexto — Como cheguei aqui

O ponto de partida foi o CTE — um projecto concreto de engenharia que cresceu até precisar de 3 braços (Claude Project para estratégia, Cowork para execução, IDE para código). Esse crescimento revelou fragilidades na forma como os braços comunicam e como o conhecimento persiste entre sessões.

A resposta foi ir "mais atrás": antes de resolver o CTE, resolver a arquitectura de base. Nasceu o CWPP — um protocolo para gerir projectos Claude Web de forma robusta. Mas enquanto se construía o CWPP, surgiu outra camada: o Knowledge Repository (onde se guarda o que se aprende) era um database flat no Notion — sem ligações, sem estrutura, sem cross-referencing.

A tentativa de resolver o Knowledge Repository revelou um problema ainda mais fundamental: não é só o repositório que está partido — é toda a função de retenção do ecossistema.

2. O Modelo de 3 Funções

O ecossistema pessoal de trabalho com AI cumpre três funções distintas. Cada ferramenta encaixa numa (ou mais) destas funções:

Modelo funcional do ecossistema. A seta de retorno tracejada representa o ciclo de knowledge que deveria alimentar futuras sessões.

PENSAR funciona

Claude Projects para estratégia e apoio a decisões. Gemini para validação cruzada e deep research. O CWPP dá estrutura a esta função: protocolo de arranque, handoffs, gestão de contexto. É a peça mais madura do ecossistema.

FAZER c/ fricção

Cowork para execução com filesystem, IDE agents para código, apps auxiliares construídas ad-hoc. Funciona, mas os handoffs entre braços são manuais e propensos a perda de contexto. A fricção é tolerável porque o PENSAR compensa com planeamento.

RETER partido

Três ferramentas, nenhuma com protocolo. O Notion existe mas é usado de forma inconsistente — sem template nem regras, torna-se mais um projecto em si mesmo. A Wiki Karpathy foi descoberta há 2 dias e tem potencial enorme, mas é uma ferramenta sem fundação. O Knowledge Repository do CWPP é flat — sem entidades, sem relações, sem graph.

Diagnóstico central: O PENSAR e o FAZER produzem knowledge continuamente — decisões, pesquisas, padrões, anti-padrões. Mas esse knowledge não tem casa. Vive na cabeça, disperso por chats antigos, ou em notas soltas. Cada sessão nova reconstrói contexto em vez de o reaproveitar.

3. Os Dois Ramos de Trabalho

O ecossistema não serve um projecto — serve dois ramos de trabalho que correm em paralelo e se cruzam:

Os dois ramos de trabalho partilham knowledge. O RETER seria a ponte entre eles — mas está partido.

Ramo 1 resolve problemas reais de engenharia com AI: o CTE (caderno de encargos), o MQT (validação de medições), o SSOT (plataforma de dados), a candidatura OE. Cada projecto produz knowledge específico — mas também knowledge transversal: legislação (Portaria 255/2023), normas (Eurocódigos), padrões de dados.

Ramo 2 resolve o "como trabalhar com AI": protocolos, arquitecturas, wikis, workflows. O CWPP é Ramo 2. Cada descoberta aqui (ex: "braços com handoff inter-braço funcionam melhor com contexto zero") é knowledge que serve todos os projectos do Ramo 1.

Insight chave: Os dois ramos não são independentes. Knowledge flui entre eles — mas hoje esse fluxo é mental, não sistematizado. A Portaria 255/2023 serve o CTE e a candidatura OE. O padrão "wiki para contexto táctico" serve o CTE e qualquer futuro projecto multi-braço. O RETER deveria ser a ponte. Não é.

4. O Problema de Bootstrap

Existe uma dependência circular:

  • Para construir o RETER, é preciso um projecto estruturado (PENSAR).
  • O projecto estruturado (CWPP) usa o Notion como state layer.
  • O Notion é exactamente uma das peças partidas do RETER.

Não se pode construir a fundação usando a fundação que ainda não existe. Isto explica a sensação de "pescadinha de rabo na boca" — cada passo atrás revela outra dependência.

A solução é quebrar o ciclo: montar um meta-projecto para o ecossistema usando uma versão simplificada do CWPP que não depende do Notion. Handoffs manuais por paste. Sem Knowledge Repository. Sem protocolos de auditoria. Apenas o suficiente para que cada sessão retome onde a anterior parou — até o RETER estar montado.

5. Porque estou neste ponto

A trajectória foi lógica e correcta:

  • CTE (projecto concreto) → revelou que projectos complexos precisam de arquitectura multi-braço
  • CWPP (protocolo) → resposta ao problema: infra para gerir projectos Claude Web
  • Wiki Karpathy → promessa de colmatar o knowledge vivo — mas precisa de fundação
  • Este diagnóstico → percepção de que o problema é mais profundo: falta a função RETER inteira

Cada passo forçou ir "mais atrás", ao nível mais conceptual. Isto é sinal de maturidade do sistema: quando a complexidade cresce, a resposta correcta é recuar ao modelo antes de avançar para a implementação.

Risco identificado: A capacidade analítica pode tornar-se armadilha. As 48h seguidas a explorar a wiki são sinal de mergulho profundo numa peça antes de ter o mapa global. É como dimensionar armadura de punçoamento antes de ter o modelo de pórtico fechado. O mapa vem primeiro.

Relatório de Diagnóstico — Sumário Executivo

Estado: O ecossistema pessoal de AI tem 3 funções (Pensar, Fazer, Reter) e 2 ramos de trabalho (Aplicações de engenharia, Fundamentos AI). O PENSAR está estruturado (CWPP). O FAZER funciona com fricção. O RETER não tem protocolo — é a falha estrutural do sistema.

Causa raiz: O RETER nunca foi tratado como função autónoma. As ferramentas existem (Notion, Wiki, KB) mas sem protocolo de uso, sem regras, sem integração. O Notion tornou-se overhead em vez de infra. A Wiki é promissora mas tem 2 dias. O KB é flat.

Impacto: Todo o knowledge produzido nas sessões de PENSAR e FAZER dissipa-se. Cada sessão nova reconstrói contexto. Knowledge cruzado entre projectos (legislação, padrões AI, decisões) não circula. Os dois ramos de trabalho funcionam em silos sem ponte.

Dependência circular: Para construir o RETER, preciso de um projecto estruturado (PENSAR). Mas o CWPP completo depende do Notion (que é RETER). Solução: versão simplificada do CWPP que não dependa do Notion.

Recomendação: Criar um meta-projecto ("Ecossistema AI" ou "Fundações") usando CWPP simplificado, com 3 ficheiros na KB (SYSTEM-PROMPT, ROADMAP, e handoff deste chat). Objectivo do meta-projecto: definir e construir a infraestrutura do RETER. Sem Notion, sem overhead, sem over-engineering.
